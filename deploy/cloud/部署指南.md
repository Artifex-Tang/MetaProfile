# MetaProfile 部署指南

从零到能用，按顺序照做即可。全程约 **20 分钟**（不含上传时间）。本指南的每条命令都在真实环境跑通过。

命令里 `<...>` 是需要你替换的内容，其余可直接复制。

---

## 第一步：确认目标机满足条件

登上目标机，逐条执行，四条都要过：

```bash
# 1. 系统（Ubuntu 20.04+ / CentOS 7+ 均可）
cat /etc/os-release | head -2

# 2. 配置：至少 4 核 8G（neo4j 吃内存，推荐 16G+）
nproc && free -g | head -2

# 3. 磁盘：至少 10G 可用
df -h /

# 4. docker 与 compose v2
docker version && docker compose version
```

**没装 docker？** 先装（需要外网）：

```bash
# Ubuntu / Debian
curl -fsSL https://get.docker.com | bash
systemctl enable --now docker

# 离线环境请向运维索取对应系统的 docker 离线安装包，本 kit 不含 docker 本体
```

**装完验证**：`docker run --rm hello-world` 能正常输出即可。

---

## 第二步：开放端口

对外只需要 **3 个端口**，在云厂商控制台的安全组 / 防火墙里放行：

| 端口 | 用途 | 是否必须 |
|------|------|----------|
| 22 | SSH 登录 | 必须（建议限制来源 IP） |
| 80 | 网站访问、HTTPS 证书签发 | 必须 |
| 443 | HTTPS | 上 HTTPS 才需要 |

> 其余端口（8000 后端 / 5432 数据库 / 6379 / 7474 / 7687）都只绑定在本机回环，
> **不要也不需要对外开放**。需要连数据库调试时用 SSH 隧道（见最后一节）。

---

## 第三步：上传安装包

在**你自己的电脑**上执行（不是目标机）：

```bash
scp metaprofile-deploy-kit.tar.gz root@<目标机IP>:/root/
```

包约 **0.81 GB**。按 300 KB/s 家庭宽带算大约 45 分钟，公司网络会快很多。

> 断了可以续传：`rsync -avP metaprofile-deploy-kit.tar.gz root@<目标机IP>:/root/`

---

## 第四步：解包并部署

回到**目标机**执行：

```bash
cd /root
tar -xzf metaprofile-deploy-kit.tar.gz
cd metaprofile-deploy-kit
bash deploy.sh
```

脚本自动完成 9 步，与屏幕上打印的 `[n/9]` 一一对应：

1. 前置检查　2. 导入镜像　3. 准备目录与前端文件　4. 启动 5 个容器（含建表，并等待全部就绪）
5. 放宽字段约束　6. 灌入演示数据　7. 补齐空值　8. 验证接口　9. 验证 MCP

第 4 步最长等 5 分钟；超时会直接报错退出并提示查日志的命令，不会带着半死的栈往下跑。
第 8、9 步的每项检查都会自动重试 5 次，偶发的慢启动不会被误报成失败。

**约 2~5 分钟**（实测本地 SSD 约 2 分钟，云主机磁盘慢会久一些）。正常结束会看到：

```
✅ 部署完成
   前端     http://<本机公网IP>
   7 工具   http://<IP>/tech?embed=1
   Swagger  http://<IP>/docs
   MCP      http://<IP>/mcp
```

### 如果第一步就被拦下

前置检查失败会直接中止，**不会做任何改动**。照着提示修即可：

| 提示 | 原因与处理 |
|------|-----------|
| `docker ✗ 未安装` | 回第一步装 docker |
| `docker ✗ daemon 没起` | `systemctl start docker` |
| `docker compose ✗ 缺 compose v2 插件` | 装 `docker-compose-plugin` 包 |
| `端口占用 ✗ 已被占用: 80` | 目标机已有 nginx/apache 占了 80，先停掉：`systemctl stop nginx` |
| `磁盘 ✗ 剩余 xG` | 清理空间，或换个数据盘（见下方"挂数据盘"） |
| `kit 完整性 ✗ 缺:...` | 安装包传输不完整，重新上传 |

### 想把数据放到独立数据盘

在跑 `deploy.sh` **之前**执行（默认目录是 `/data`）：

```bash
mkfs.ext4 -F /dev/vdb                    # 注意确认盘符，此操作会清空该盘
mkdir -p /data && mount /dev/vdb /data
echo "UUID=$(blkid -s UUID -o value /dev/vdb) /data ext4 defaults 0 2" >> /etc/fstab
```

---

## 第五步：验收

浏览器打开 `http://<目标机公网IP>`。

> ⚠️ **必须手动输入 `http://` 前缀**。Chrome 默认会先试 HTTPS，直接输 IP 会打不开。
> 如果本机开了 clash 等代理，把这个 IP 加进代理的 bypass 列表。

逐项确认：

- [ ] 首页能打开，左侧有导航菜单
- [ ] 技术画像 / 项目画像 / 机构画像 / 人员画像四个页面都能进，列表有数据
- [ ] 随便点开一条画像详情，**关系图谱能显示，节点上的中文正常**（若显示 `???` 见常见问题 3）
- [ ] 新技术发现页面，"关联"列的数字可以点开，弹出网络图
- [ ] `http://<IP>/docs` 能打开 Swagger 接口文档
- [ ] 部署脚本第 9 步 7 个 MCP 端点全部 ✓，且「无 token 访问被拒(401)」

## 第六步（可选）：启用 HTTPS

### 先决条件，缺一不可

1. **有域名**，且 A 记录已解析到目标机公网 IP
   验证：`dig +short <你的域名>`，返回的 IP 要和目标机一致
2. **大陆节点必须完成 ICP 备案**，否则 80/443 会被运营商拦截，证书签发必定失败
   备案周期 **7~20 个工作日**，要上 HTTPS 请尽早启动
3. 安全组已放行 443
4. 第四步已完成，网站在 80 端口正常访问

> 纯 IP 无法申请证书（Let's Encrypt 只签域名）。
> 不想备案可以换香港 / 新加坡节点，免备案。

### 执行

```bash
cd /root/metaprofile-deploy-kit

# 先用测试环境试跑一遍，确认流程通（不消耗正式配额）
bash enable_https.sh <你的域名> <你的邮箱> --staging

# 上一步没报错，再签正式证书
bash enable_https.sh <你的域名> <你的邮箱>
```

脚本会：校验解析 → 校验验证路径可达 → 签发证书 → 切换 nginx 配置（80 自动跳 443）
→ 配置每天自动续期。

完成后访问 `https://<你的域名>`。

### 收尾：限制 MCP 的访问域名

```bash
echo "MCP_ALLOWED_HOSTS=<你的域名>" >> /data/deploy/.env
cd /data/deploy && docker compose -f docker-compose.readonly.yml up -d backend
```

## 第七步：接入 MCP 客户端

系统提供 **7 个独立的 MCP 端点**，一个工具一个地址，使用方按需只挂自己要的那几个。
全部经 80/443，不需要单独开端口。

| # | 工具 | 端点 | 工具数 |
|---|------|------|--------|
| 1 | 技术画像工具 | `/mcp/tech-profile` | 8 |
| 2 | 项目画像工具 | `/mcp/project-profile` | 7 |
| 3 | 机构画像工具 | `/mcp/org-profile` | 7 |
| 4 | 人员画像工具 | `/mcp/person-profile` | 7 |
| 5 | 扫描监测工具 | `/mcp/scan-monitor` | 3 |
| 6 | 新技术发现工具 | `/mcp/new-tech-discovery` | 3 |
| 7 | 选题服务工具 | `/mcp/topic-selection` | 2 |

合计 37 个工具，**全部只读**：写入、导入、LLM 补全、触发扫描的接口一个都没暴露。

### 拿 token

`deploy.sh` 首次部署会自动生成一个 Bearer token 并写进 `/data/deploy/.env`，
部署结束时也会打印出来。之后重跑 `deploy.sh` 会复用同一个（否则已经发出去的配置会失效）。

```bash
grep MCP_AUTH_TOKEN /data/deploy/.env
```

### 生成分发用的配置

```bash
cd /data/deploy
C="docker compose -f docker-compose.readonly.yml"
TOKEN=$(grep '^MCP_AUTH_TOKEN=' .env | cut -d= -f2-)

# 7 段独立配置（分发给不同使用方）
$C exec -T backend python scripts/gen_mcp_config.py   --base-url http://<你的IP或域名> --token "$TOKEN"

# 或者一份合并配置（一次挂全部 7 个）
$C exec -T backend python scripts/gen_mcp_config.py   --base-url http://<你的IP或域名> --token "$TOKEN" --combined
```

输出形如：

```json
1，技术画像工具
{
  "mcpServers": {
    "techProfile": {
      "url": "http://<IP>/mcp/tech-profile",
      "headers": {
        "Authorization": "Bearer mp_xxxxxxxx"
      }
    }
  }
}
```

上了 HTTPS 就把 `--base-url` 换成 `https://<你的域名>`。

### 自测某个端点通不通

```bash
TOKEN=$(grep '^MCP_AUTH_TOKEN=' /data/deploy/.env | cut -d= -f2-)
curl -s -X POST http://<IP>/mcp/tech-profile   -H 'Content-Type: application/json'   -H 'Accept: application/json, text/event-stream'   -H "Authorization: Bearer $TOKEN"   -d '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-06-18","capabilities":{},"clientInfo":{"name":"test","version":"1.0"}}}'
```

返回里含 `"serverInfo":{"name":"techProfile"` 就是通了。不带 token 会返 401。

> **换 token**：编辑 `/data/deploy/.env` 改掉 `MCP_AUTH_TOKEN`，然后
> `cd /data/deploy && docker compose -f docker-compose.readonly.yml up -d backend`。
> 旧 token 立即失效，记得重新分发配置。
>
> 把 `MCP_AUTH_TOKEN` 留空则完全不鉴权，任何人都能调用——只建议在内网环境这么做。

## 常见问题

**1. 浏览器打不开，一直转圈**
依次排查：安全组 80 放行了吗 → `curl http://localhost` 在目标机上通吗 →
输的是 `http://` 不是 `https://` 吗 → 本机代理 bypass 加了吗。

**2. 页面能开，但列表全空**
数据没灌进去。看日志：`cd /data/deploy && docker compose -f docker-compose.readonly.yml logs backend | tail -50`

**3. 关系图谱的节点名显示成 `???`**
灌 neo4j 时编码丢了。重灌，注意那个环境变量一个字都不能少（密码就是部署时的 `NEO4J_PASSWORD`，没设过就是默认 `password`）：

```bash
cd /data/deploy
cat mock_data.cypher | docker compose -f docker-compose.readonly.yml exec -T \
  -e JAVA_TOOL_OPTIONS=-Dfile.encoding=UTF-8 \
  neo4j cypher-shell -u neo4j -p "${NEO4J_PASSWORD:-password}" --format plain
```

**4. 重启后端后前端报 502**
等 10 秒会自动恢复（nginx 每 10 秒重新解析后端地址）。还不行就
`docker compose -f docker-compose.readonly.yml restart frontend`。

**5. 想连数据库看数据**
不要开放端口，用 SSH 隧道。在**你自己电脑**上执行：

```bash
ssh -L 5432:127.0.0.1:5432 -L 7474:127.0.0.1:7474 root@<目标机IP>
```

保持这个窗口开着，然后本机连 `localhost:5432`（数据库/用户名都是 `metaprofile`），
neo4j 浏览器开 `http://localhost:7474`。

## 日常运维

```bash
cd /data/deploy
C="docker compose -f docker-compose.readonly.yml"

$C ps                    # 看容器状态
$C logs -f backend       # 看后端日志
$C restart backend       # 重启后端
$C down                  # 停止（数据保留）
$C up -d                 # 重新启动
$C down -v               # ⚠️ 停止并删除所有数据，需要重跑 deploy.sh
```

### 换演示数据的数量

```bash
cd /data/deploy
C="docker compose -f docker-compose.readonly.yml"

# 在容器里重新生成，每类 60 条
$C exec -T backend python scripts/gen_mock_data.py --sql-only --count 60

# 取出生成的文件
docker cp $($C ps -q backend):/app/deploy/mock_data.sql   ./mock_data.sql
docker cp $($C ps -q backend):/app/deploy/mock_data.cypher ./mock_data.cypher

# 清空重灌（会删掉现有全部数据）
$C down -v
cd /root/metaprofile-deploy-kit && bash deploy.sh
```

### 只更新前端页面

前端文件是挂载进去的，不用重建镜像：

```bash
# 你自己电脑上：cd frontend && npm run build && tar -C dist -czf dist.tar.gz .
scp dist.tar.gz root@<IP>:/data/
# 目标机上：
rm -rf /data/dist/* && tar -xzf /data/dist.tar.gz -C /data/dist
# nginx 自动生效，无需重启
```

## 这套系统装了什么

```
目标机（单机 Docker）
├── frontend   nginx，对外 80 / 443
├── backend    后端接口 + MCP 服务，只绑本机 8000
├── postgres   四类画像数据
├── neo4j      实体关系图谱
└── redis      统计缓存
```

运行在**只读模式**：所有写入、数据采集、大模型补全的接口都会返回 503。
这是刻意设计的——本部署面向演示与查询，不承担数据生产。

更详细的技术说明见同目录 `MANUAL.md`。
